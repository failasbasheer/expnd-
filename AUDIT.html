✓ Fixed Correctness · layout account_setup.dart · showCurrencyPicker

Currency symbols wrapped onto a second line

Problem
Multi-character symbols (AED, SAR) overflowed the fixed 36px symbol slot and wrapped — rendering as “AE / D” and “SA / R”. First thing many Gulf-region users would see at setup.
Cause
A rigid SizedBox(width:36) holding 18px black-weight text with no fit constraint.
Fix
Wrapped the symbol in a left-aligned FittedBox(scaleDown) with maxLines:1. Single-glyph symbols stay full size; long ones shrink to fit one line.
✓ Fixed Visual bug wallet_view.dart · _cardStack

Ghost text bleeding through the stacked wallet cards

Problem
Collapsed cards showed faint fragments of the card beneath — “…NCE”, “…LE CREDIT” — leaking through their headers. Reads as a rendering glitch on the app’s most tactile screen.
Cause
Back cards were dimmed with Opacity<1, making each card’s peek strip translucent so the card below showed through.
Fix
Keep every card fully opaque; dim depth with a black scrim painted on top (ColoredBox in a clipped Stack) instead of lowering opacity. Same perspective, zero bleed.

P1Data-viz legibilityanalytics_view.dart · Balance Trend

The trend line can’t be read as values — and overshoots its own peak

Issue
No Y-axis labels or end-of-line value, so the curve is decorative, not informative. The smoothing spline also overshoots the data, adding a visible hump above the true maximum — it misrepresents the numbers.
Fix
Add a min/max gridline value and an emphasized endpoint dot with its amount. Switch to a monotone (clamped) interpolation so the curve never rises above a real data point.
P1Task flowadd_transaction.dart

The amount field sits below the fold, under 15 category tiles

Issue
Entering an amount is the whole point of “Add Transaction,” yet it requires scrolling past the full category grid to reach it. The primary input should never be the last thing found.
Fix
Lift amount above the category grid, or pin it as a sticky header/footer so it’s always in view while the category scrolls.
P2Consistencyhome_shell.dart · profile_view.dart

Unlabeled scope makes the same metric look contradictory

Issue
Home shows 10 transactions and a $2,733 balance (current month); Profile shows 12 and +$3,548 (all-time). Both correct, but with no scope label they read as a bug.
Fix
Add a quiet qualifier — “this month” vs “all time” — next to each figure so the difference is obviously intentional.
P2Truncationhome_shell.dart · _accountsRow

Account names clip to “Chase Checki…”

Issue
The dashboard account chips truncate common names mid-word, which looks unfinished on the primary screen.
Fix
Widen the chip, drop the label a point, or allow a second line — the balance already has room below.
P2Light themehome_shell.dart · _TabBar

Gold FAB has weak separation on the light tab bar

Issue
Win-yellow on the near-white (#F4F4EF) tab bar loses its edge in light mode; the button’s prominence drops.
Fix
Add a subtle ink hairline ring or slightly stronger depth shadow to the FAB in light mode only.
P2Data-vizanalytics_view.dart · Income vs Expenses

Bars float without a baseline when history is thin

Issue
With only two months of data the bars are sparse and hang without an axis or scale, so the tiny single-month dot looks broken.
Fix
Draw a zero baseline, set a minimum bar width, and label the Y scale so early-usage charts still feel intentional.

What’s already excellent

The reasons this reads as a finished product, not a template.

✓Consistent design language. Hard-edged neoPOP tokens (radius, depth, uppercase labels) applied uniformly across every screen.
✓Both themes designed. Light mode isn’t an inversion — gold shifts to a legible amber, contrast holds throughout.
✓Honest empty states. “No transactions this month · Tap + to add your first one” guides instead of showing a void.
✓Motion with intent. Animated counters, spring card stack, cross-faded tabs, height-tweened sections — restrained, not gratuitous.
✓Accessibility wired in. Semantics on the tab bar and FAB, Dynamic Type honored then clamped so layouts can’t break.
✓Tactile feedback. Haptics gated behind a user setting and used consistently on taps and confirmations.
✓Trustworthy money model. Balances derive from transactions as the single source of truth — figures reconcile across screens.
✓Fluid everywhere. iOS-style momentum + edge-swipe back applied app-wide for a native feel on both platforms.
